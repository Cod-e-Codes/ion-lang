# Ion bug hotspots

## Type checker (`src/tc/`)

- **Use-after-move**: moved values in branches, loop bodies, struct field partial move
- **Lasting borrow liveness**: a loan stays live until the last use of every binding that holds it. A carrier used only in one `if` arm is not live in the other (`test_borrow_if_arm.ion`). A use inside a loop still covers the whole loop. A literal index is its own path (`test_index_borrow_distinct.ion`, `test_index_borrow_same_error.ion`). Disagreeing loop exits move the binding after the loop (`test_loop_exit_disagree.ion`). Statements after `break` are not reentry (`test_loop_dead_after_break.ion`). `Copy` includes aggregates of `Copy` fields with no `impl Drop` (`test_copy_struct.ion`). `const` accepts integer widths, low-bit `as`, and `match` on `bool` and integers (`test_const_match_cast.ion`). `for` over `Iter<T>` moves the iterator (`test_iter_for.ion`, `test_map_iter.ion`). A move closure is a struct, not a function pointer (`test_move_closure.ion`). `Vec` and `String` start with `ion_alloc_t` (`test_allocator.ion`). Carriers are copies (`let c = a`), field and index reborrows (`let d = &mut a.x`, `let d = &mut a[i]`), tuple and `match` results that yield the reference, assignments (`c = a`), enum values (`Option::Some(a)`), and struct literals (`Hold { v: a }`). A reference created inside that value (`Hold { v: &mut s }`, `Option::Some(&mut s)`, `(&mut s.x, 1)`, or a `match` arm that yields `&mut s.x`) is that loan too, and it is live everywhere the holding value is live. A `match` arm that stores the reference in a local and then yields the local keeps that loan on the match result (`test_borrow_match_yield_local_error.ion`). An enum, struct, or array that holds the reference keeps the loan until that binding leaves scope. An inner statement sequence must not release a loan registered in an outer scope. Name collection must walk `match`, method calls, `try`, send/recv/spawn, array and tuple literals, and casts. A use inside a loop covers the whole loop. Disjoint fields stay legal (`test_borrow_last_use.ion`, `test_borrow_nested_use_error.ion`, `test_borrow_copy_error.ion`, `test_borrow_match_use_error.ion`, `test_borrow_reborrow_error.ion`, `test_borrow_tuple_error.ion`, `test_borrow_match_alias_error.ion`, `test_borrow_assign_error.ion`, `test_borrow_index_reborrow_error.ion`, `test_borrow_enum_ref_error.ion`, `test_borrow_get_ref_yield_error.ion`, `test_borrow_struct_ref_error.ion`, `test_borrow_struct_fresh_error.ion`, `test_borrow_enum_fresh_error.ion`, `test_borrow_tuple_fresh_error.ion`, `test_borrow_match_fresh_error.ion`, `test_field_double_mut_borrow_error.ion`). A non-`Copy` move into a closure conflicts with a reference carrier that is still in scope, including one that is never read (`test_closure_unused_borrow_error.ion`). A use of the owner after that carrier's last use, outside a closure, is unchanged (`test_unwrap_after_borrow.ion`).
- **Match through a reference**: `match` on `&Struct` or `&mut Struct` reborrows. Copy fields bind as the value. Other fields bind as `&T` or `&mut T`. Codegen keeps the scrutinee pointer (`Pair* match_val = r`) and takes the address of a non-copy field. It must not copy the struct or null and free the field (`test_match_ref_struct.ion`). A reference payload (`Option<&int>`) binds as the pointer (`int* p = arg0`). It must not load the referent (`test_match_option_ref.ion`).
- **Drop partial move**: moving a non-Copy field out of an `impl Drop` value is an error on field access and on `match` patterns. A wildcard or `..` leaves the field for the destructor (`test_drop_partial_move_error.ion`, `test_drop_match_partial_move_error.ion`, `test_drop_match_rest.ion`).
- **Reference escape**: `&` stored in struct, returned, sent on channel, captured by `spawn`. Locals and params must also reject off-stack stores (`Box<&T>`, `Vec<&T>`); `is_reference_containing` on decls/returns is not enough (`test_box_ref_let_error.ion`). `Option<&T>` stack temporaries from `get_ref` stay legal.
- **Send**: non-Send types on channels or in spawn closures; `Box` and channel element variance. Unbounded type parameters are not `Send`: generic `T` is stored as `Type::Struct("T")`, and `is_send` is true for that name only with a `T: Send` bound in `type_param_scopes`. Unknown struct/enum names fail closed (same default as `&T`). Instantiation still checks declared bounds (`test_unbounded_t_send_error.ion`, `test_trait_bound_send_error.ion`). Do not treat missing decls as Send.
- **Recursive types**: `is_reference_containing` / `is_send` / `is_eq_type` / `type_needs_drop` need a visiting set; without one, `Box`/`Vec`/`Option<Box<…>>` self-reference stack-overflows at decl time. Representability (`InfiniteSize`) treats only `Box`/`Vec`/`RawPtr` as size boundaries; `Option<Node>` is still infinite size; `Option<Box<Node>>` is not. Do not “stop at Box” inside the no-escape walker or `Box<&T>` silently passes.
- **Generic enum `None`**: `Option::None` has no payload, so `T` is inferred from `expr_expected` / return type (let annotation, struct field, call argument, built-in value parameter, return, assignment target, or array/tuple/repeat/enum-payload element). Unannotated `let empty = Option::None` must error with cannot-infer, not a later `Option<T>` vs `Option<Box<Node>>` mismatch (`test_option_none_unannotated_error.ion`). Same-expression `Node { next: Option::None }` is fine (`test_option_none_struct_field.ion`). Direct call arguments `take(Option::None)` are fine (`test_option_none_call_arg.ion`). `send(&tx, Option::None)` infers from `Sender<T>` (`test_send_option_none.ion`); `Box::new(Option::None)` infers from an expected `Box<Option<...>>` (`test_box_new_option_none.ion`). Array/tuple elements, `[value; N]`, assignment, and `return [Option::None]` use the same helper (`test_array_option_none.ion`, `test_tuple_option_none.ion`, `test_array_option_some.ion`). `send` is `Expr::Send`, not a user `Call`, so call-arg expected-type plumbing does not cover it.
- **Generic enum payload vs expected `T`**: placeholders are only uninferred type-parameter names (`Type::Struct("T")` / empty `Generic { name: "T" }`), never `Type::Int`. With an expected instantiation, check the payload against the substituted type and do not clobber a concrete inferred param (`test_option_some_bool_int_error.ion`, `test_option_some_string_int_error.ion`). Matching payloads still work (`test_option_some_int.ion`, `test_option_some_bool.ion`).
- **Match-arm result types**: `infer_block_result_type` reads recorded `TypeInfo` expr types plus control-flow shape (diverge vs value). It must not call `check_expr` again after `check_stmt` (`test_vec_get_putback_named.ion`).
- **Match ownership join**: fall-through arms join like `if`. Restoring the pre-match env is a hole (`test_match_move_join_error.ion`). `block_falls_through` / `block_contains_break` must walk `Stmt::Expr(Match)`.
- **Match on `&GenericEnum`**: peel `Ref` before building the type-param subst map in `add_pattern_bindings` (see `test_match_ref_generic_enum_arith.ion`); bare `if let Type::Generic` misses `Ref { Generic { … } }` and leaves bindings as `&T`
- **Nested match constructors**: recurse `add_pattern_bindings` on payload type (unknown nested enum is `TypeMismatch`). If every covering arm uses nested constructors, exhaust the inner enum (`test_nested_match_nonexhaustive_error.ion`). IR specializes to nested `Match` on extracted payloads; cgen must not half-emit nested temps, and rvalue last-stmt `Match` uses `generate_match_block` (`test_nested_match_pattern.ion`, `test_nested_match_named.ion`). A catch-all binding mixed with a nested constructor must declare that name from the outer scrutinee (`test_nested_match_catchall_binding.ion`); do not clone the catch-all body into the inner match as a nameless wildcard. Wildcard and whole-enum `default:` arms must be a compound statement (`default: { ... }`) so a declaration after the label is valid C; Clang (macOS CI) rejects the GNU extension GCC accepts.
- **Generic enum lit at fn-pointer calls**: `IREexpr::EnumLit` carries the TypeInfo instantiation. Call codegen must also look up `fn(...)` locals, not only named functions, or `f(Result::Ok(7))` emits `(Result)` instead of `(Result_int_int)` (`test_fn_ptr_enum_lit_arg.ion`, `test_try_fn_literal.ion`).
- **Postfix `?`**: keep `Expr::Try` through type checking (do not rewrite to `Match` in `merge_modules`). `Option` and `Result` stay eligible by enum name and §8.1 variant shape. Another owned enum is eligible when it has one success variant: `Ok` or `Some` with one positional payload, or the single payload variant when those names are absent. The function must return that same enum. `ReadResult` qualifies in a function that returns `ReadResult` (`test_try_readresult.ion`). `SetResult` and a bare error enum do not (`test_try_setresult_error.ion`, `test_try_math_error.ion`). References and `spawn` stay errors. Residual coloring uses `current_return_type`; reject inside `spawn` (`check_spawn_block` does not reset return type). Lower to `IREexpr::Match` with success yield and `Return` of the other variants (`test_try_result_ok.ion`, `test_try_spawn_error.ion`).
- **`resolve_type_name` and `&Enum` params**: must recurse into `Ref` so `&Flag` becomes `Ref { Enum }` (parser stores enum names as `Struct`); otherwise calls get `expected &Flag, got &Flag` from Struct vs Enum mismatch
- **`resolve_type_name` generic params**: must rewrite `Struct` to `Enum` inside `Generic` (and other composites). `Result<int, MyError>` vs `Result::Err(MyError::Bad)` otherwise prints `expected Result<int, MyError>, got Result<int, MyError>` (`test_result_custom_enum.ion`)
- **MethodCall vs Call**: parser emits `Expr::MethodCall`; tc/IR/cgen must handle both
- **Module visibility**: `pub` vs private across `import`

CLI errors use `TypeCheckError` Debug form (`UseAfterMove { ... }`). LSP reformats them in `src/lsp/`.

## Codegen (`src/cgen/`)

- **Integer wrap**: `+ - *` emit same-width unsigned C ops then cast back; never rely on `-fwrapv`. `/` `%` insert zero and signed MIN/-1 panics; shifts insert width panics. `AssignIndex` must bounds-check like `Index` (`test_int_wrap.ion`, `test_div_zero_panic.ion`, `test_assign_index_oob.ion`).
- **String UTF-8**: `ion_utf8_valid` on from_literal / push_str; `push_byte` rejects `>= 0x80`. OOM and grow failure `ion_panic`, not NULL. `String::from_utf8` returns `Option<String>` (`test_string_from_utf8.ion`).
- **Struct field move-out**: owned fields null after partial move on the next statement (`board.items = NULL`; deferred when the move is a call argument)
- **Vec::push lvalues**: struct variables and field paths use `&item`, not compound literal (`vec_push_struct_var_uses_address_of_lvalue`)
- **Array typedef names**: `type_to_c` for `[T; N]` is the typedef name (`arr_int_2`), never `T[N]`. Emit `typedef T name[N]` innermost-first before Vec/Box/field uses. Nested arrays and `Box<[T;N]>` / `Vec<[T;N]>` need this (`test_nested_array.ion`, `test_box_array.ion`, `test_vec_array.ion`). C arrays are not assignable: Box/Vec copies and match payload bindings use memcpy.
- **Enum emission order**: collect generic instantiations from enum variant payloads and close generic struct/enum templates (substitute collected params into fields/payloads until fixpoint). Forward-declare non-generic structs and enums so `Option_ref_Op` can mention `Op*` (`test_vm_execute.ion`). Emit complete generic enums (`Option_int`) before non-generic enums that embed them (`Hold`). Same order in single-file `generate_c` and multi-file `generate_module_source`. Generic enums must also exist before tuple typedefs that store them by value (`test_tuple_option_none.ion`, `test_enum_option_payload_none.ion`, `test_generic_struct_option_none.ion`). Array typedefs of tuples wait until the tuple typedef exists (`test_array_of_tuples_option_none.ion`). `collect_generic_from_type` must walk `Type::Tuple` (and TupleLit `elem_types`); walking only nested exprs misses `Option::None` which has no payload expr.
- **Nested enum compound literals**: GCC rejects `(Option_int){...}` as a designated field of a tuple or struct. Emit brace-only `{ .tag = N, .data = { } }` there. Call-site and let inits stay `(Option_int){...}` (`test_option_none_call_arg.ion` cgen `take((Option_int)`).
- **Tuple mangle**: `tuple_type_name` sanitizes `*` and brackets when names include `Vec` types
- **Match scrutinee move-out**: pattern payload bindings null `match_val_N.data.variant_*` fields when ownership transfers (`statement_match_payload_move_neutralizes_scrutinee`); whole-enum binding arms clear active variant payloads via `emit_match_scrutinee_whole_enum_moved_out` (`whole_enum_binding_neutralizes_scrutinee_payloads`). IR infers `enum_type` from the scrutinee when arms use binding/wildcard only (`infer_match_enum_name`). Rvalue arm result assignment (`result_var = expr`) must `mark_moves_in_expr` like `let`/`return`, or a bare owned tail (`s;`) is dropped twice (`test_match_expr_rvalue_string.ion`, `rvalue_match_owned_string_arm_result_marks_payload_moved`). A value-pattern binding of a type that needs drop copies the place and then clears it (`match_val_N.field = NULL` or the zero value). Those bindings are registered on an arm scope, so their drops stay inside the arm block (`test_match_struct_string.ion`). An `@` binding of a drop value is the place later field patterns move from.
- **Match expression value**: `IREexpr::Match.result_type` is the match result (`Void` for a statement). As an operand, codegen declares `_ion_match_res_N`, assigns each arm result, drops `match_val` inside the statement expression, and yields the temp. A caller that already has a result variable (`let`, `return`) must not wrap another statement expression (`test_match_value_rvalue.ion`).
- **Pattern-binding monomorph**: generic rewrite and capability resolution bind pattern names to the field or payload type before walking the arm. A missing struct field is a compiler panic. Do not record the whole scrutinee type on every field (`test_match_pattern_generic.ion`). A match through `&Enum` records the type checker's binding (`&V` when `V` is not `Copy`, including a type parameter). Substitution replaces the parameter and keeps that reference, so a later `Copy` instantiation still passes a pointer (`test_stdlib_map.ion` `for_each` on `int`). Copy fields of a concrete `&Status<int>` still bind by value (`test_match_ref_generic_enum_arith.ion`).
- **Generic match through a reference**: peel `Ref` before choosing the enum monomorph. A bare `Type::Generic` check misses `&Slot<K, V>` and `find_enum_instantiation` then emits the first `Slot` (`Slot_int_Val` inside `place_int_int`). `substitute_types_in_expr` still must substitute `Match.scrutinee_type` (`examples/handle_table`).
- **String literal pattern**: compare `len` and `memcmp` on the bytes. Do not call `ion_string_from_literal` or `ion_string_equals` for the pattern (`test_match_string_lit.ion`). `let s: String = "..."` still allocates.
- **Return unwind**: all function exits use `emit_function_return` (`ret_val`, `scope_emit_return_unwind`, `goto epilogue`), including diverging `return` inside rvalue `match` arms (`rvalue_match_divergent_return_unwinds_owned`). Value-producing rvalue arms still assign and `break` from the `switch`.
- **Loop unwind**: `break`/`continue` must `emit_frame_cleanup` from the loop body frame through inner `if`/`match` frames (clone; do not mark `dropped`). Always set `loop_break_label` so `break` inside `match` inside `while`/`for` gotos the loop exit, not the `switch`. Emit `loop_break_N: ;` and the continue label the same way. A label directly on a declaration is not valid C; Clang (macOS CI) rejects the GNU extension GCC accepts (`test_stdlib_string.ion`). `continue` uses `loop_continue_label` so `for` steps still run (`test_loop_continue_nested_if_drop.ion`, `test_for_continue_drop_step.ion`, `test_match_break_in_while.ion`).
- **Tuple/array drop**: `type_needs_drop` must walk `Type::Tuple` and `Type::Array`; drop glue is `path.fN` and `path[i]` (`test_tuple_string_scope_drop.ion`, `test_array_string_scope_drop.ion`).
- `Box`, `Vec`, `String` layout vs `runtime/ion_runtime.h`
- **IR must use `TypeInfo`**: after a successful type-check, every lowered expression id has a canonical type. Missing id is a compiler bug, never a syntactic `int` fallback (`let x = y`, `Box::new(StructLit)`, `Box::unwrap`, `Enum::Variant`). Tests: `test_unannotated_let_non_int.ion`, `test_box_new_struct_let*.ion`, `test_box_unwrap_struct_let.ion`, `test_enum_unannotated_let.ion`.
- **`Box::unwrap`**: copy `T` out, then `ion_box_free` the box pointer; do not drop `T` (nested heap in the payload would double-free). The allocation is an `ion_alloc_t` header before `T`. `ion_box_free` steps back one header. It is inline in the runtime header, not a symbol in `ion_runtime.o`. Move-mark the argument, including a consuming call inside `+`, a unary operator, or an index, so scope-exit drop does not free again (`test_box_unwrap_same_scope.ion`, `test_box_unwrap_binop.ion`). A `run` exit code cannot catch the leak; Linux CI leak-sanitizer step uses `detect_leaks=1` on unwrap tests.
- **`Vec<T>` element drop**: scope-exit drop must iterate remaining elements when `T` needs destruction, then `ion_vec_free`. `Vec::get` of such `T` hollows the slot; `Vec::set` drops the previous element. Copy `T` stays memcpy-only (`test_vec_string_scope_drop.ion`, `test_vec_get_set.ion`). Do not drop nested owned fields through a `get_ref` binding.
- **`String::len`**: null-check the `String*` value, not `&local` (`-Waddress` under CI `-Werror`)
- **`len` / `get_ref` routing**: the callee is `{Type}::{method}` from `extract_type_name_for_method`. Slices and arrays are `Slice`, arenas are `Arena`, strings are `String`, vectors are `Vec`. Codegen matches that full callee. Dispatching on the bare method name sends `s.len()` and `arena.get_ref(h)` to the Vec builtin (`test_slice_len.ion`, `test_method_call_basic.ion`, `test_arena_get_ref.ion`).
- **Tuple typedef order**: `emit_tuple_typedef_ordered` emits a nested tuple typedef before the outer one (`tuple_int_int` before `tuple_tuple_int_int_int`). The collection is a `HashMap`, so iterating it directly is not dependency order (`test_nested_tuple_eq.ion`).
- **Field replacement**: assigning a non-Copy field drops the previous value, then stores. The assignment type is the owned field type. Reading that field through `&` or `&mut` is still a reborrow (`test_field_replace_drop.ion`). `stdlib/map.ion` grows by assigning the new slot vector.
- **Aggregate `==`**: structs, enums, and arrays compare fields, the active variant payload, or elements. C `==` stays for scalars. Tuples and `String` have their own paths (`test_aggregate_eq.ion`, `test_nested_tuple_eq.ion`).
- **Generic instantiation**: a later monomorph pass must not emit a second function with a name already in the program. `place` is called from both `insert` and `grow`. The instantiation loop retries at most eight times. If calls are still open, panic. Do not emit the last batch as the open template.
- **`Vec::set`**: wrap runtime int in `SetResult`; statement form still emits the enum then `(void)` (`test_vec_set_result.ion`).
- **`select`**: copy in the same `try_recv`. Register waiters, recheck empty, then wait. Try-then-register lost a concurrent send (`test_select_blocking_send.ion`). `default` is timeout 0; no default/timeout is `-1`; Ion `timeout(ms)` with `ms < 0` panics at runtime and a literal is a type error (`test_select.ion`, `test_select_timeout.ion`).
- **`spawn` statement vs expr**: `spawn { };` outside `scope` stays `ion_spawn`. `let h = spawn { };` is `ion_spawn_joinable` and has type `JoinHandle<T>`. A non-void block mallocs a result slot. `ion_join_value` copies `T` out. Drop of `JoinHandle` is `ion_thread_detach` (`test_join.ion`, `test_join_value.ion`). `scope` joins handles still owned in that block (`test_scope_join.ion`). A handle moved out is not joined there (`test_scope_move_out.ion`).
- **Protocol endpoints**: `send` and `recv` on `Type::Endpoint` consume the endpoint and return the next step. The payload struct rides two crossed channels. A second use of the same endpoint is `UseAfterMove` (`test_protocol.ion`, `test_protocol_move_error.ion`). Tuple destructure must move-check the initializer before the pattern bindings shadow those names.
- **`Vec` typedef collect**: `walk_referenced_expr` must walk `Match` arm bodies (`collect_vec_types_impl` reads that pass). A `let buf: Vec<u8>` only inside `Option::Some` otherwise never emits `Vec_uint8_t` (`test_file_rw.ion`).
- **String literal call args**: parameters typed `String` need `ion_string_from_literal` at the call site, not only on `let s: String = "…"`. Pass compilation-wide `TypeInfo.function_params` into multi-file cgen (`println`, `io::println`, `io_println`) so imported callees see `String` (`test_string_call_arg_literal.ion`, `test_multi_fmt_io.ion`).
- **Reborrowed field → `&Vec` / `&String` param**: non-copy `FieldAccess` through `&Struct` is already `&T` in Ion but loads as `T*` in C; user calls need `&(base->field)` so arity matches `T**` (see `test_ref_struct_field_to_ref_vec_param.ion`). Nested embedded paths use `.` after the first hop (`&(w->inner.data)`). Builtins keep bare field loads via `vec_ion_ptr_expr`.
- Single-file merge (`merge_modules`) vs `--mode multi` divergences. Public functions are renamed `{alias}_{name}`. Bare calls inside that module are rewritten to the mangled name. Private names stay bare (`math::clamp` calls `min` / `max`; `string::trim_ascii` calls `slice`).
- `extern "C"` calls only inside `unsafe` blocks in source; cgen must not strip guards
- **Extern C only**: linkage other than `"C"` is a type error; do not register those functions. If non-C still reaches cgen, panic (`compiler bug: non-C extern reached cgen`) rather than skip the prototype (`test_extern_rust_error.ion`).

## Runtime

- Channel success path claims a slot with atomics and copies `elem_size` bytes. A pthread wait runs only when the buffer is full, empty, or disconnected, and only after the waiter is registered and the claim is retried. Notify only when a waiter is registered. One receiver. Concurrent sender drop must not lose a count, free the channel early, or skip waking `recv`. Receiver shutdown of a sender that has not claimed a slot returns closed and does not copy. Capacity 1 uses the same rules. Destroy runs only when both sender and receiver counts are 0, and drops each buffered element once (`test_channel_contention.ion`, `test_channel_shutdown.ion`, `test_channel_queued_string_drop.ion`, `test_channel_send_closed.ion`, `test_select_blocking_send.ion`)
- `spawn` thread lifecycle, joinable `ion_thread_t`, detach-on-drop
- `ion_file_t` fopen/fread/fwrite/fclose
- Windows: `-lws2_32` for socket examples; pthread via MinGW
